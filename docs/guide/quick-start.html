Getting started

Quick start

Create a .sapi file, point URL: at your API (or a mock), and run snapapi on that file. The older .snaptest extension still works.

1. Write a suite

Save this as users.sapi. Indentation is optional; keywords are not.

SUITE: Users
DESC: Create a user and read it back
TIMEOUT: 10
URL: https://api.example.com
HEADER Content-Type: application/json

TEST: Create User
TAG: users write
  POST: /users
  AUTH: bearer ${TOKEN}
  BODY: {"name": "Jane", "email": "jane@example.com"}
  EXPECT: status == 201
  EXPECT: body contains id
  SAVE: userId FROM $.id

TEST: Get User
TAG: users
SETUP: Create User
  GET: /users/${userId}
  EXPECT: status == 200
  EXPECT: json $.email == "jane@example.com"
  EXPECT: header Content-Type contains json

2. Provide variables

${TOKEN} is interpolated from the process environment, then --env or a file next to the suite (users.env, .env, or the only sibling *.env), then SET / SAVE. A .env file looks like:

TOKEN=your-bearer-token

3. Run it

snapapi users.sapi
snapapi users.sapi --env .env
snapapi tests/ suites/auth.sapi

Directories are scanned for *.sapi and *.snaptest. The CLI prints a tree: suite name, each test, request lines with status and duration, then PASS / FAIL and a summary.

4. Try the same shape without Python

Open the playground, pick Create + SAVE, and click Run. That sample talks to the in-browser mock at /api/users instead of https://api.example.com.

Sample files in this repo

  • tests/recommended.snaptest — current DSL against the local mock (${BASE_URL})
  • tests/test_suite.snaptest — classic REQUEST: / DATA: / EXPECT: STATUS syntax
