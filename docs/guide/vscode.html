The language pack lives in snapapi-language/. There is no separate language-server process.

Editor

VS Code / Cursor

The snapapi-language folder is a VS Code extension for .sapi files: syntax highlighting, snippets, completions, lightweight diagnostics, and run commands that shell out to the CLI. The older .snaptest extension is still associated.

What you get

  • Highlighting for current and legacy keywords, HTTP method aliases, ${VAR}, JSON bodies, and // comments
  • Snippets for a suite skeleton, GET/POST tests, EXPECT variants, SAVE, AUTH, HEADER, and QUERY
  • Keyword completions, plus test-name completions after SETUP: / TEARDOWN: / SUITE-SETUP: / SUITE-TEARDOWN: / DEPENDS:
  • Diagnostics on edit/save: unknown keywords, missing request paths, unknown SETUP/TEARDOWN/SUITE-SETUP/DEPENDS names (including cheap IMPORT resolution), HEAD: paths, and REQUEST: OPTIONS /path. HELPER: is a procedure, not a test case.
  • SnapAPI: Run current file and Run test at cursor (the latter passes snapapi --name)

Install from this repo (debug)

  1. Open the snapapi-language folder in VS Code or Cursor.
  2. Press F5 to launch an Extension Development Host.
  3. Open a .sapi file.

If the workspace is the SnapAPI repo root, set the launch argument to --extensionDevelopmentPath=${workspaceFolder}/snapapi-language.

Copy into extensions

cp -R snapapi-language ~/.vscode/extensions/deekshithpoojary.snapapi-language-0.1.0

Restart the editor. For Cursor, use ~/.cursor/extensions/ instead.

VSIX

cd snapapi-language
npx @vscode/vsce package
code --install-extension snapapi-language-0.1.0.vsix

The CLI must be installed separately (pip install -e . from the repo root, or put snapapi on PATH).

{

  "snapapi.envFile": "${workspaceFolder}/.env"
}

Run current file

With a .sapi editor focused, run SnapAPI: Run current file from the command palette. The file is saved, then the extension runs snapapi <file>. Run test at cursor uses the nearest TEST: above the cursor and passes --name. Output goes to the SnapAPI channel; the status bar shows the last result while a .sapi file is active.

The playground does not use the extension. Use it to learn the DSL; use the CLI (or these commands) for real HTTP.
